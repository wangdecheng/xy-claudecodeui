# 公有云问题分析流程设计

状态：三份提示词已写入分析工作根目录，静态检查通过；实际模型加载与端到端取证尚未验证。本文记录确定的行为、迁移与验证结果。

## 用户已明确的要求

- 公有云问题分析无需用户上传日志，由分析技能获取运行环境证据。
- 本工作台公有云分析固定面向 prd，不提供 pre 分析或 pre/prd 选择。
- 公有云数据库默认按 MySQL 理解；现有数据库字段继续必填，无需为此调整页面或后端校验。
- 所有公有云服务统一使用 xy-pub-bug-fix，包括 sdk-server 和 sdk-callback；不再单独路由到 xy-sdk-pub-bug。
- 公有云分析前按服务分别定位 release_pub 开头、分支名末尾日期最新的分支，再读取该分支最新远端提交；不按提交时间或版本号排序分支，不给所有服务套用同一分支。
- 无 ONES 链接也允许直接描述问题并开始分析；有 ONES 时按技能读取，无 ONES 时使用当前问题 ID 关联证据，不虚构 ONES 编号。
- 公有云和私有云都严格只分析，不修改任何业务代码，不生成代码补丁或进入技能的修复方案/代码修改阶段；该约束放在统一入口。
- 最终分析上下文位于用户指定的 customer-onsite-analysis 工作根目录，每个问题保留独立上下文。
- 分支无法唯一确定或远端刷新失败时，报告阻塞，不猜分支或使用未验证的旧缓存。
- 工作台的技能适配集中在 public-cloud.md，通用技能保持原有独立调用约定。
- 开始或恢复实质分析时刷新远端并记录新基线；保留历史报告与旧基线，重新核查受变化影响的结论。

用户给出的工作根目录是本机核查目标，不应因此把个人绝对路径加入应用代码或通用配置。

## 已确定的技能路由

公有云问题统一进入 xy-pub-bug-fix 的分析阶段；SDK 不再保留固定分支例外。技能中的逐服务取证、部署版本与最新代码双视角、证据不足时阻塞的规则统一适用。

公有云提示词核心约定（已写入运行文件，以下为设计摘要）：

> 当前问题选择公有云分析时，统一使用 xy-pub-bug-fix 的取证流程，包括 sdk-server 与 sdk-callback，并应用本工作台的明确适配规则：固定 prd、默认 MySQL、ONES 可选、仅分析。每个服务在刷新远端后，独立选择 release_pub 开头且名称末尾日期最新的分支，以其最新远端提交判断当前行为；另取证故障部署 commit，用于解释故障日志。用户无需上传日志，通过显式 --kubeconfig ~/work/tools/k8s_config/prd_config 只读取证，按故障时间和唯一请求标识检索各副本的当前与归档日志。有 ONES 时读取原始工单资料，无 ONES 时使用当前问题 ID 和用户描述。取证与分析产物归入当前问题目录，最终只输出已证实根因或待补证据；不进入修复阶段，不生成代码补丁，不修改业务代码。

该片段必须与工作根目录现有“本地日志必填”等规则分流，不能只追加到仍然无条件生效的私有云要求之后。工作台的分析边界不因技能包含修复能力而扩大。

技能适配必须集中写明四个差异：允许无 ONES 输入、固定 prd、按分支日期选择分析基线、只执行分析阶段。其余取证细则通过引用读取技能，避免复制出另一套诊断流程。无 ONES 时报告标注问题 ID 与“未关联 ONES”，不套用虚构的 onesId。

最终交付物保持支持人员可读的业务结论与可执行取证动作。部署镜像、分支、完整 commit、日志来源和源码位置保存在当前问题目录的技术证据中；“不改代码”不禁止读取源码、只读 Git 分析或写分析报告。已有修复只能在证据充分时报告其状态，不自动实施、提交或部署。

工作台适配将通用技能的环境范围收窄为 prd，不再询问选择 pre 还是 prd。若输入明确属于 pre，应说明其不属于本工作台的公有云分析范围，不得把 pre 事件当成 prd 事件检索，也不得切换至 pre。prd 无法访问时按技能报告阻塞，不回退其他环境。

MySQL 是公有云默认数据库类型，不代表已经证明某个数据库连接、schema 或实际数据属于该问题。保留用户填写的数据库字段；出现与默认值不同的明确输入时先核实，不静默覆盖。私有云继续使用原有数据库选择与方言规则。

## 统一入口与分流文件

按用户提出的结构设计：工作根目录的 CLAUDE.md 作为统一入口，公有云与私有云各有一个流程文件。以下路径相对分析工作根目录，而非工作台源码仓库：

```text
customer-onsite-analysis/
├── CLAUDE.md
├── prompts/
│   ├── public-cloud.md
│   └── private-cloud.md
└── <当前问题目录>/
    └── problem.json
```

| 文件 | 职责 |
| --- | --- |
| CLAUDE.md | 锁定当前问题目录，读取该问题元数据，确定分析类型，再明确读取对应流程文件；保存问题隔离与证据真实性等共用约束 |
| prompts/public-cloud.md | 公有云技能入口适配、固定 prd、默认 MySQL、无需上传日志、逐服务分支解析与远程只读取证；统一使用 xy-pub-bug-fix |
| prompts/private-cloud.md | 承接现有私有云流程：客户/迭代选分支、本地日志解压、多副本日志检索、数据库方言及现场执行 SQL |

路由规则：

1. 从已锁定的当前问题目录读取 problem.json，先判定分析类型，再检查该类型所需资料。
2. 当前配置值 release_pub 进入公有云文件，并兼容此前的 pub 值；两者都是分析类型入口，不作为具体 Git 分支名。直接选择具体 release_pub_* 分支的入口扩展不在本轮范围内。
3. 已明确的私有云迭代进入私有云文件；字段缺失、未知值或与用户明确指定的云类型冲突时，先确认类型。客户名称不能单独作为云类型依据。
4. 入口按条件明确要求完整读取一个流程文件，不在入口无条件导入两个文件。读取流程文件属于共享规则访问，允许访问当前问题目录之外的指定 prompts 文件；兄弟问题目录仍受隔离约束。
5. 共用规则只保留一份。上传日志必填、数据库只能交现场查询、客户分支映射等有云类型适用范围的要求移入私有云文件；公有云取证规则集中在公有云文件。
6. 新会话与恢复会话均以当前问题元数据确定流程；检测到分析类型变化时重新确认当前分析范围，旧日志与结论不得直接混用。

实施时还要核查首轮用户消息及后端系统追加词，避免它们继续无条件要求私有云资料。拆分之外，需要在公有云文件中显式落实已经确定的技能入口、分支选择和仅分析约束。

迁移以工作根目录 CLAUDE.md 的调整前工作区内容为源，写入前再次比较源文件，防止覆盖期间的并发改动。三份文件已生成；保留原始文件备份，未修改权限配置、通用技能或业务代码。

## 已确定的分支规则

选分支只比较分支名末尾的日期；选中后再取该分支最新远端提交。一个旧日期分支刚合入 hotfix，不会因此成为最新日期分支。候选日期必须为可解析的有效日期；逐服务记录候选、日期、选中分支与完整 commit。

故障部署版本与最新日期分支可能不同，必须分别记录。部署版本用于解释故障，最新日期分支用于分析当前行为和判断是否有已有修复；不能要求部署 commit 一定属于最新日期分支，也不能仅凭最新源码推导历史故障。

“分支日期”“提交时间”“故障日志时间”分别表述。日志按故障时间及唯一事件标识获取，不按文件修改时间替代事件匹配。

## 阻塞与历史保留

| 条件 | 已确定的行为 |
| --- | --- |
| 无有效日期分支、最大日期对应多个不同分支或远端刷新失败 | 报告具体缺失/候选并停止该服务的代码结论，不猜分支、不回退 master、不把旧缓存称为最新 |
| 通用技能与工作台在输入、环境、分支或阶段上有差异 | 读取技能并应用 public-cloud.md 集中声明的工作台规则；不修改通用技能独立调用约定 |
| 恢复旧问题时分支或提交已经变化 | 开始或恢复实质分析时刷新远端，记录新基线并重新核查受影响结论；保留原报告与旧基线，不能无声覆盖历史 |
| 入口缺少服务或存在明确的服务/环境冲突 | 列明缺失或冲突证据，补齐后继续；不凭相似服务名或其他问题推断 |

历史报告和源码证据始终绑定当时的完整 commit。新基线形成新的分析记录；只查看历史报告不需要刷新远端，恢复取证和代码分析时才执行刷新。

## 实施前验证计划

使用实际运行工作台、当前问题目录和可访问服务的真实仓库/远端元数据；不以迎合实现的虚构日志证明业务完成。

- 以一个真实 prd 公有云问题，按现有表单填写数据库但不上传日志，验证能够开始 prd 远端取证；出现“请先上传日志”或“请选择 pre/prd”即失败。
- 检查公有云命令显式使用 prd_config，报告标注 prd；使用 pre_config 或混入 pre 事件即失败。数据库必填校验保持原行为。
- 分别选择 sdk-server 与一个真实非 SDK 服务，检查实际均加载 xy-pub-bug-fix；SDK 仍加载旧专用技能即失败。
- 在真实仓库核对分支日期后缀、候选、选中分支和远端完整 commit；按提交时间选错日期分支或跨服务复用错误分支即失败。
- 使用无 ONES 链接的真实问题描述，验证进入取证且报告绑定当前问题 ID，不因 ONES 缺失阻塞、不虚构工单编号。
- 检查实际分析输出和服务源码工作区差异：只产出取证与分析记录；要求用户审批代码修复、生成补丁或修改业务源码均为失败。
- 用故障发生时间及请求标识核对实际日志来源；仅用最新应用日志替代故障时间日志即失败。
- 保留一个真实私有云问题做回归，确认仍使用其上传资料和客户/迭代规则。
- 在新会话与恢复会话中检查规则是否一致生效；只查看提示词字符串不视为端到端验证完成。
- 检查实际读取记录：公有云会话读取 public-cloud.md，私有云会话读取 private-cloud.md；两份流程无条件同时加载即失败。
- 校验缺失或冲突的云类型不会自动落入私有云，也不会读取兄弟问题；指定共享流程文件可正常读取。
- 恢复一个已有报告的问题，记录新取得的分支与 commit，检查旧报告及旧基线仍可追溯；新旧证据混写或覆盖历史为失败。
- 核对通用技能文件未发生工作台专用改动，且工作台公有云流程集中包含四项适配；修复阶段仍被明确排除。

端到端验证需选择可访问的真实问题及仓库，记录实际执行入口、目标、命令和结果；缺少可访问案例或无法执行时如实列为未验证。
